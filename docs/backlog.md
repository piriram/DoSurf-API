**`scripts/validate_locations.py`.** 세 신호를 넣었고 **틀렸던 좌표 8곳이 전부

**설계 중 임계값이 두 번 바뀌었다. 둘 다 실측이 문서 안을 반박한 것이다.**

| 안 | 폐기 이유 |

채택한 겹침 임계값은 **2km** 다. 정상 최솟값(사천진↔사천 2.12km · 인구↔기사문

**도구가 곧바로 제 수정을 잡았다 — 영덕 부흥이 두 번 틀렸다.**

### 10. 노출도 변환 — 해변별 차등

**이게 "해변마다 다른 값" 요구의 본체다.** 양양 6곳이 같은 값인 건 격자 붕괴
때문이고 모델로도 Windfinder 로도 안 풀린다.

재료는 준비됐다 — `shore_normal.json` 32곳 + 수집 중인 파향.
**막는 것은 공식 선택과 #9(방위 검수)다.**

| | 절대 감쇠 | 상대 노출도 |
|---|---|---|
| 식 | `H × cos(θ)^k` | `H × cos(θ)^k / mean(지역)` |
| Windfinder 일치 | **잃는다** | 유지 |
| 물리적 정직성 | 높다 | 정규화로 일부 포기 |

2026-09-27 시뮬레이션에서 드러난 것: 절대 감쇠는 **모든 해변을 줄인다**
(21시 0.40m → 0.14~0.23m). 지금 파고는 Windfinder 와 4~6cm 로 맞는데
감쇠를 걸면 멀어진다. 목표가 「Windfinder 와 비슷하게」라면 상대 노출도가 맞다.

정할 것: 공식 · `k` 값 · 창 밖 처리(완전 차단 vs 감쇠) · 신뢰도 노출 여부.

|---|---|---|
| 고흥 남열 해돋이 | 스웰창 **30°** · 방위 100° | 32곳 중 유일하게 60° 미만이다. west_south 유일 지점이라 옆과 비교할 수 없다 |
| 다대포 ↔ 광안리 | 18.5km 인데 방위차 **90°** | 부산은 대조 지점도 없다(#13) |
| 중문 | 고도 **62m** | 절벽인지 좌표 오류인지 사람이 봐야 한다 (#7) |

좌표 검증(#1)이 끝나 **좌표 오류로 인한 방위 오류는 걸러졌다.** 고성 천진은
30°→120° 로 풀렸고(#4), 동해 대진은 80°→140°(#6), 강릉 남애는 240°→160°(#6b)
로 **과대평가가 교정됐다.** 남은 셋은 좌표가 아니라 지형 판단 문제다.

  다르게 나와도 **025 로 되돌리면 문섬·섶섬은 첨두주기가 사라진다**

### 16. 기상청 부이를 기준값으로 — 순환논리를 끊는다

**지금 대조는 모델 대 모델이다.** Windfinder 가 WW3 를 쓰고 `ncep_gfswave*` 도
같은 소스라, 4주 결론 「후보들이 실질적으로 같은 정확도」가 사실은
**「다 똑같이 Windfinder 를 닮았다」**였을 수 있다. 부이는 관측값이라 이
순환을 끊는 **유일한 후보**다.

조사는 끝났다 — `scripts/buoy_coverage.py` 로 격자 일치를 쟀다.
**10곳이 맞고 커버리지가 17 → 23곳**이 된다. 강릉 4곳이 여기서 채워진다
(지금까지 「Windfinder 지점을 못 찾았다」로 비어 있던 곳이다).
수치와 부이 좌표는 `AGENTS.md` 「기상청 부이」 절에 있다.

**막힌 것: 활용신청.** 키 문제가 아니다 — 2026-10-01 에 실제로 호출해 봤다.

| 호출 | 결과 |
|---|---|
| 단기예보 (기존 용도) | ✅ `NORMAL_SERVICE` |
| `kma_buoy.php` · `sea_obs.php` | ⛔ `403 활용신청이 필요한 API` |

**기상청 API허브는 API 마다 따로 신청을 받고, 지금 키는 단기예보만 돼 있다.**
키는 Secret Manager 의 `dosurf-kma-api-key` 에 멀쩡히 있다.

> 2026-10-01 에 「키가 이 맥에 없어서 막혔다」고 잘못 적었다가 고쳤다.
> `AGENTS.md` 에 「자격증명은 iCloud 인계 폴더에 있다」만 보고 **Secret Manager
> 를 확인하지 않은 것**이다. 같은 날 수집 토큰을 거기서 꺼내 쓰고도 그랬다.

**오너가 할 일:** [기상청 API허브](https://apihub.kma.go.kr/) 로그인 →
해양관측(해양기상부이·파고부이) **활용신청**. 무료고 보통 바로 승인된다.

신청이 되면 순서대로:

1. `kma_buoy.php`(해양기상부이) · 파고부이 엔드포인트 실호출 — 파고·파주기 확인
2. 어느 부이가 아직 운영 중인지 (**강릉·구엄·신창·죽변이 2025 종료 예정**)
3. 관측 시간 축이 `ALLOWED_HOURS`(0,3,…,21시)와 맞는지
4. `model_compare.py` 에 기준을 하나 더 다는 형태로 붙인다

**apihub 와 data.go.kr 는 키 체계가 다르다.** 이 저장소 키는 apihub 쪽
(22자 `authKey`)이라 `getWhBuoy`(data.go.kr `serviceKey`)에 넣으면
`SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 난다. **apihub 로 가는 쪽이 싸다** —
키를 그대로 쓰고 신청만 하면 된다.

**#13(busan)은 이 길로 안 풀린다.** 간절곶이 26~52km 로 격자가 다르다.
