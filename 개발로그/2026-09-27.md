## 1. 파주기 축을 첨두로 맞췄다

`model_compare.py` 가 `wave_period`(평균주기)만 받아 Windfinder 첨두주기와
맞대고 있었다. `wave_peak_period` 를 함께 요청하고, 첨두가 오는 모델은 첨두로
재고 못 주는 모델은 평균으로 폴백한 뒤 `period_kind` 에 남긴다. 파주기 순위는
**첨두끼리만** 매긴다.

**실측(7모델)**: 첨두를 값으로 주는 것은 `ecmwf_wam025`·`ecmwf_wam` 뿐이다.
나머지는 변수를 거부하지 않고 24개 전부 `None` 을 돌려준다. 그래서 파주기
후보가 파고보다 적고 **파고 1위와 갈리는 게 정상**이다.

기존 54건은 평균주기 축이라 롤업이 파주기 집계에서 분리한다. 파주기 표본은

## 4. 격자가 다르면 대조 결론이 전이되지 않는다

"대조 좌표가 수집 좌표와 같냐"는 질문에서 시작해 실측했다.

| | 값 |
|---|---|
| 격자가 다른 15곳의 파고차 | 중앙값 **0.020m** |
| 격자가 같은 14곳 | **0.000m** |
| 모델 1·2위 편향제거 MAE 차 | **0.001m** |

**공간 차이가 모델 차이를 20~80배 압도한다.** 모델 호출 좌표를 해변으로 옮기는
것은 해법이 아니다 — 기준값이 지점 좌표의 예보라 같은 크기의 공간 오차가
기준값 비교로 들어온다.

그래서 `scripts/grid_coverage.py` 를 만들어 **적용 범위를 좁혔다.** 지점별로
격자가 같은 해변(적용 가능)과 다른 해변(적용 불가)을 가르고 `model_compare` 가
출력에 찍는다. 현재 16/29곳.

이 격자 불일치가 **보정계수 금지 규칙에 구조적 근거를 하나 더 준다.**
모델 선택은 인접 격자로 어느 정도 전이되지만 편향은 전이되지 않는다.

| 영덕 부흥 | 내륙 40m · 바다까지 6km · 바다 방위 0/36 | 2025-04-23 | **격자 바뀜** |
| 고성 천진 | **13km 북쪽**, 죽왕면 송지호보다 북쪽 | 2025-04-23 | **격자 바뀜** |
| 포항 월포 | 해안에서 0.94km 내륙 (24m) | 2025-03-14 | 값은 그대로 |

**영덕 부흥과 고성 천진은 그동안 다른 해역의 파도를 보여주고 있었다.**

**왜 안 드러났나.** `cell_selection=sea` 가 육지 좌표든 엉뚱한 좌표든 가장 가까운
해상 격자를 찾아 **그럴듯한 숫자를 계속 돌려준다.** `null` 도 에러도 안 난다.

실제 위치는 오너가 준 지도 스크린샷으로 확정했다 — 부흥해변은 남정면 부흥리
(노바서핑스쿨 동해대로 3676), 월포는 청하면 월포리(스웰서프), 천진은 토성면
천진리(렛미서프 천진해변길 35-5). 웹 검색만으로는 "장사리"라는 틀린 답이 나왔다.

아직 남은 의심: **남애3리**(죽도와 0.4km 로 겹친다), **동해 대진**(27m),
**중문**(62m, 절벽일 수 있고 `jungmun` 지점과 격자가 일치하므로 건드리면 위험).
고도 API 일일 한도에 걸려 내일 이어간다.

## 7. 해변별 차등 — 재료는 만들었고 공식은 미결

`scripts/shore_normal.py` 로 32곳의 방위·스웰 창을 구했다. 결과는 일관적이다
(yangyang 6곳 50~65°, sokcho 3곳 50~70°, 제주는 남 145~180° / 북 0~350°).

**격자 붕괴가 확인됐다.** 양양 6곳은 어느 모델을 써도 격자 하나에 다 들어가
파고가 전부 0.64m 다. `best_match`(8km)도 마찬가지다. Windfinder 를 완벽히
재현해도 안 풀린다 — 양양 일대에 Windfinder 지점도 하나뿐이다.

노출도 변환 시뮬레이션에서 **절대 감쇠의 함정**이 드러났다. 노출도는 1을 넘지
않으므로 모든 해변이 줄어드는데, 지금 파고는 Windfinder 와 이미 4~6cm 로 맞는다.
감쇠를 걸면 **목표에서 멀어진다.** 대안은 지역 평균을 1로 두는 상대 노출도다.

공식 선택은 제품 결정이라 미뤘다. `docs/marine-data-plan.md` 맨 위 참조.
